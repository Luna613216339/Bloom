## 一、用户已经拍板的（2026-11-02）

试玩第一段之后：

- **分裂球通过**。五彩外观暂时保留，白模里也保留五彩。
- **联动门通过。**
- **续命进正式序列。** 价格不急，随便写个占位数字。解谜关给不给续命还没定，维持现在的默认（不给）。
- **硬球用户还没看到**，继续当样关，放进备选池让用户再看。
- **最喜欢第 7 关「闸」那种动静结合**：一队在走的球 + 一团静止的球。备选关多做这一类。
- **静止球群要有 idle**：不能完全静止，太僵硬；小幅移动，但不能改变通关策略。
- **分裂球 + 门的关有难度、不可或缺，但要更多引导**，放在曲线哪里要想清楚，别让玩家直接退游。
- **美术先做白模**：现在太花、太潦草、有锯齿。配色用最简单的，不要五颜六色。用户以后自己探索美术风格，再盖在白模上。
- **中英文两个版本都要。** 现在已经是一套界面、一张中英对照词条表（`Loc.cs`）加语言切换，不是做两套；新加的文案照样中英各写一份。
- **这一阶段以测试白模为主。**

## 二、做什么

建议顺序：先 1、2（白模能看了，后面的截图和效果图才有底），再 3、4、5，最后 6。

### 1. 测试用主菜单：滚动列表

- 关卡选择从小方块网格改成**竖向滚动列表**，关卡会越来越多。
- 每行：关号 / id、名字、**一行中文说明它的特色**（方便用户边玩边记感受），再标一下它属于正式关、样关还是备选关。
- 这是测试阶段的菜单，不追求最终形态。说明文字只要中文。
- 新中文字不在子集字体里。测试菜单可以用系统字体顶上（例如 `Font.CreateDynamicFontFromOSFont` 取苹方 / 冬青黑体，只在 macOS 编辑器和 macOS 包里用），不需要下载东西。正式关卡名要进游戏时再重做子集字体（下载完整 Noto Sans SC 仍然要先问用户）。

### 2. 白模化

- 目标：干净、精致、没锯齿，看得清玩法状态；以后能把用户定的美术风格整层盖上去。
- 正式关卡永远白底（老规矩）。球、门、墙、笼子改成克制的灰阶，最多一个强调色表示「着火 / 在扩散」。不同状态（静止、着火、火星、硬球的壳、普通门 / 联动门）一眼能分清。分裂球保留五彩。
- 锯齿：先查清楚来源（贴图分辨率、过滤方式、抗锯齿、Game 视图缩放、没有描边），用编辑器截图放大对比确认修好了。备份开发笔记里记过以前修过的三个来源，先读。
- 外观和玩法分开：画法集中在一处（比如一个外观层 / 主题类），以后换美术只改这一处。配色仍然只从 `BallPalette.cs` 取。
- 无尽模式和商店皮肤这次不动。

### 3. 静止球群的 idle 实验

- 做 4–5 种动法让用户比：上下浮、左右摆、整团慢转、呼吸（整团微微胀缩）、每颗各自轻微漂移，或者别的。
- 幅度要比连锁够得着的距离（普通球约 0.94，蛇里的球约 0.825）小得多；被点着的球停止 idle。
- 交付成同一关的几个变体（比如第 7 关闸 × 每种动法），用户在菜单里挨个点开比。
- 用自动测试确认：每个变体原来的解法还能过，「随手一点」通过率和不动时差不多。差太多就说明改了策略，要收小幅度。

### 4. 大量备选关

- 备选池总数做到 **40 个以上**（现有 17 关算在内），用户从里面挑正式关卡。
- 重点做**动静结合**，也覆盖分裂球、联动门、硬球、续命、笼子、旧的蛇和环。
- 每个备选关都要：自动测试跑出的解法、「随手一点」通过率、菜单里的一行中文特色、关卡表里一行、总览图里一格。长得像的就别留。
- 备选关在菜单里和正式关分开（单独一段或标签）。正式序列等用户挑完再排。

### 5. 分裂球 + 门的引导

- 在最难的分裂球 + 门关之前，做 2–3 个循序渐进的小关，每关只教一件事（火星会飞、火星会被关着的门弹回、开关门能给火星改路）。
- 在关卡表里提出它们放在曲线哪里、为什么不会劝退。
- 能用画面或布局引导就别加文字。

### 6. GPT 效果图

- 用 Codex CLI（带图像生成）出 **4–6 个美术风格方向**的效果图，同一个构图（建议拿白模的真实截图当参考图喂给它），16:9。
- 存进 `Docs/效果图/`，按数字编号命名（`01.png`、`02.png` …），旁边一份 `说明.md` 写每张图是什么方向。
- 生成后用发送文件的方式直接发到对话里给用户看。
- 调用 Codex 按 `~/.claude/CLAUDE.md` 的经验来（模型、档位、省上下文的写法）。提示词里不要提任何参考作品。

## 三、工具上的变化

- **用户会打开 Bloom 工程并一直开着。** 编辑器开着时命令行 batchmode 编译用不了（工程被锁），改用 Unity MCP：
  - `Unity_RunCommand` 执行 C#：`AssetDatabase.Refresh()` 触发重新编译、调 `BuildScripts.BuildAutotest()` 打测试包、进出 Play 模式。
  - `Unity_Camera_Capture` / `Unity_GetConsoleLogs` 截图和看控制台。白模和 idle 都要亲眼截图检查过再交付。
  - 打好的测试包照样从命令行无头跑，不受编辑器影响。
- **额度**：每做完一大块看一眼用量（`mcp__ccd_session_mgmt__get_usage`）。5 小时窗口过了 80% 就先提交、把进度写进 `Docs/交接.md`，保证撞墙停下后用户说「继续」就能接上。
- 如果 MCP 连不上（报 Unity not detected），先看工程是不是真开着；还不行就请用户关掉 Unity，退回命令行 batchmode。

## 四、不做什么

- 续命定价、正式关卡的金币来源
- 最终的正式关卡序列（等用户从备选里挑）
- 无尽模式规则、商店、音频
- WebGL 打包、发布到 itch.io
- 下载字体或装新包（要先问）

1–6 都做完，或者遇到必须问用户的事（见第一段任务说明第七节），按五段格式交付，同时写进 `Docs/交接.md`。交付前开一个全新的子代理独立检查一遍。
