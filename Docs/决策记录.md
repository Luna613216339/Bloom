## 2026-11-08 Bloom 的收尾范围（用户定）

- **关卡数量不再加。** 现在的关够了，接下来只做这六件，做完 Bloom 就算完成、封箱：
  1. 精调关卡
  2. 精调难度曲线（排正式序列）
  3. 新机制教学 / 引导关精调
  4. 美术蒙皮（在白模上盖 04 极简几何方向）
  5. 音乐音效
  6. UI 优化
- 理由：给项目画一条终点线，剩下的时间能放心投入，不再无限扩展。
- **星级不做。** 用户：很多关的挑战就在于要收齐所有球，不引爆全部也能过就没难度、没趣味了；而且工作量大，破坏体验。「过关一律清空全场」不变。
- **经济从简**：数值差不多、不崩就行，不精调。
- **皮肤商店要做**，等美术方向定了再盖皮肤。皮肤仍然只在无尽模式生效，正式关卡永远白底。
- 手机端默认不做，用户提起再说。发布 itch 仍然要用户明说。

## 2026-11-03 第三阶段的关卡设计决定（Fable 定，用户在睡觉，**要用户试玩确认**）

- **门在分裂球关里只当"时机"，不当"前置步骤"。** 用户说开关、分岔"开局先把门点开"无聊。放行（顶替开关）把开闸变成放队伍走、再掐火星落下的时间；分岔保留飞行中切换；引导关里的门仍然是"点火前准备好"，因为它们的任务是教门会弹火星。
- **分裂球那一族每关一个形状**：喷泉、倒立、T 形、从右边来、斜着来、上下分岔。不再有"左一团 + 桥 + 右两团"。
- **硬球关的套路是"第二把火要绕路或者等"**：双锁用快火星先碎壳、慢桥火补刀；门闩用先碎壳、等一拍再放队伍撞上来。硬球规则本身没改（1 秒冷却）。
- **烟花撤掉换成流星**：转环四射的火星打不全六团，做不到全清；流星只有一个五彩球、一条线、两团，卡时机才够得着。
- **漂流回来了**，但只留一条线当目标：旧版两个角落各一团，一下只够一团。
- **瓮中的蛇改成盘进笼子**（路不循环）：撞死墙乱弹是随机的，总有球弹出门去。
- 回旋去掉固定方向：火星方向由点的位置决定，才有"从哪点"这个谜题。
- 关号又重排了一次（36 关）。关卡表第二列是用户 11-02 试玩那版的编号。

## 2026-11-02 第二阶段试玩后的关卡规则（用户定，原话在 `试玩反馈-第二阶段.md`）

- **过关一律清空全场**（含逃跑球、硬球，不含火星）。不做星级。代码里每关 `Target = TotalBalls`，不再手填目标。
- **随机散布关只留在无尽模式**，不进有编号的关卡（初开、繁星、密林撤下）。
- 撤下：漂流（目标做不到全清；"整团漂流撞墙反弹"的动法留着）、折返（队伍碰到球群就掉头，玩家会困惑）、再来一下（等于逼玩家花钱续命）。
- 万花筒（原来 5 个圆环的第 10 关）和螺旋 / 三叶 / 蜿蜒当调剂关。
- **白模配色**：普通球一种中灰（#7D7D7D），不分深浅、两队也不分；特殊球带颜色（逃跑球蓝、硬球墨绿、分裂球五彩），着火朱红。
- **idle 按关定**：圆形小团"呼吸"（用户觉得和上下浮差不多、甚至更好）；蛇不加；左右摆、慢转、各自漂不要。

## 2026-11-02 硬球改规则（Opus 定，**用户还要试玩确认**）

- 用户试玩：没有「必须打两次、炸两次」的感觉。查下来是规则问题，不是关卡目标：旧规则是"两把**不同的**火各碰一次就炸"，
  而连锁里每颗烧着的球都算一把火 —— 硬球旁边两颗邻居先后着火就够了，所以在一团里几乎和普通球一样，点在它旁边也一下就开。
- 新规则：第一次被火碰到，**外壳碎掉**（一圈细线散开，不传火），剩下一颗球；壳碎后 1 秒内碰到它的火全部作废，
  之后**再来一把火**才炸。所以火得从另一条路绕回来，或者靠火星、移动的球把第二把火送到。
- 理由：这样"打两次"是玩家看得见、要去规划的事（火要绕回来 / 要有第二个来源），而不是同一波火顺带完成。
- 硬壳样关改成一圈球顶上一颗硬球：点在硬球旁边，火绕一圈回来第二次打它；点在正对面，两头的火同时到，只打掉壳。

## 2026-11-02 美术方向（用户定，看完六张效果图）

- **基准是 04 极简几何**：平涂、流畅，有一点剪纸动画的感觉。下一轮效果图都在这个方向上出变体。01 的配色可以参考，但它的质感像毛毡，不要。
- **白底，普通球用灰色或黑色，只有特殊球可以带颜色。** 所有关卡都一样。
- **球必须是完美的圆**，不加叶子、纹理、材质（否定 03 水彩、06 陶土）。
- **深色底加发光的风格（02 霓虹、05 深海）永远不要。**
- **普通球被引爆就是「炸一下，然后消失」**，要好看，不做真的火焰或爆炸动画。比较显眼的火球效果最多只给玩家点下去的那一颗。

## 2026-11-02 第二阶段的技术与规则决定（Fable 定，纯技术）

- **外观和玩法分开**：正式关卡里每样东西长什么样都从 `Look.cs` 取（色表仍在 `BallPalette.cs`）。
  以后换美术只改这一处。无尽模式和商店皮肤不走它，照旧用主题配色。
- **白模的样子**：白底；球四档灰（散布关循环当标签，蛇形关沿身体从深到浅、看得出队伍方向）；
  唯一的强调色是朱红 `#F04E2A`，只用于"着火 / 在扩散"（被点着的球、玩家点出的圈、火星拖尾）。
  墙、笼子、门都是深灰。分裂球和火星保留五彩（用户定）。硬球的壳仍是贴图里那圈透明缝。
- **门重画**：关着的普通门 = 斜条纹，联动门 = 横杠，开着的门 = 空心框。
  以前开着的门是隐形的，错车那种"两扇开着的门"玩家根本不知道门在哪；现在能看见。
  旧的交叉网纹贴图缩小后是一团噪点，这是用户看到的"锯齿"的主要来源之一。
  门的贴图按门的长宽比生成、Sliced 模式填满 1×1，花纹在任何尺寸的门上粗细一致。
  坑：SpriteRenderer 换 sprite 时会把 Sliced 的 size 重置成贴图原尺寸，门就被画成长宽比的倍数长；每次换贴图后都要再设 size = (1,1)。
- **锯齿排查结论**：球的边缘本身没问题（MSAA 4x 已开、贴图有 mipmap，1920×1080 离屏渲染放大看是干净的）；
  难看的是门贴图的网纹噪点，以及 Game 视图不在 1x 时的预览假象（开发笔记坑 19）。
- **静止球群的 idle**：`IdleDef` 五种动法，只作用于关卡里摆好的静止球（蛇和散布球不动），
  被点着的球立刻停。幅度：整团一起动的（浮 / 摆 / 转）0.12 或 8°/秒，会拉开球距的（呼吸 0.05、各自漂 0.04）
  压得很小 —— 第 7 关那圈相邻 0.7、够得着 0.825，余量只有 0.125。五种做成第 7 关的五个变体给用户比。
  限制：呼吸和各自漂只对球距余量够的关安全（3 涟漪内圈、14 / 33 / 34 / 41 那些半径 0.9 的团只剩 0.04 余量，会断链）；
  浮 / 摆 / 转是整团刚体动，哪关都能挂。
- **关卡池**：`LevelPool` = 正式 / 样关 / 备选 / 实验。测试菜单按它分段打标签，总览图右上角标 S / C / E。
- **测试菜单用内置动态字体**：说明文字的汉字不在子集字体里，内置字体在编辑器和 macOS 包里会退到系统字体。
  `Font.CreateDynamicFontFromOSFont` 在 IMGUI 里字形全错，不可用。正式关卡名进游戏仍要重做子集字体（要先问用户下载）。
- **火只能往后传，追不上往前走的队伍**：队伍速度 1.7，膨胀半径增长只有 0.75/秒，前面的球永远跑在火前面。
  所以"动静结合"的配方是：静止的团 + 从团里穿过去的队伍，点队头或点团，后面的球会自己涌进火里；
  或者用关着的门把队伍停成一条静止的线，这时火才能沿着它传。候车、门闩两关就是反过来用这一点（开闸是错的）。
- **硬球的局限**：点出的圈本身算一把火，所以紧挨着硬球点永远能开它。硬球谜题只在"硬球不止一颗"
  （双锁）或"缝不能点"（门闩那种缝落在门上）时才成立。
- **Codex 出图**：`codex exec --enable image_generation -s workspace-write -i 参考图`，模型会把图存到
  `~/.codex/generated_images/` 再 cp 过来；`exec` 默认不带这个工具，要显式 enable。

## 2026-11-02 第一段试玩反馈（用户定）

- **喜欢「动态 + 静态」组合**：第 7 关闸那种一队在走的球、加一团不动的球。以后多做这一类。
- **静止球群不能完全静止，要有 idle**：小幅地动（上下、左右、旋转、呼吸都可以探索），但**不能改变通关策略**。幅度要比连锁够得着的距离小得多。
- **分裂球 + 门的关有难度、不可或缺，但要更多引导**，而且要想清楚放在难度曲线的哪里，别让玩家直接退游。
- **美术改成白模**：现在太花、太潦草。先做干净的白模，配色用最简单的，不要五颜六色。用户探索好美术风格后，再盖在白模上面。目标是更精致、没锯齿（怀疑是没描边）。
- **美术效果图要联合 GPT 出**（Codex CLI 带图像生成）。
- **关卡要更多备选**，从多的里面挑。用户反馈慢，下一阶段可以让 Fable 自己长时间摸索。

- **目标是游戏更好玩，不是展示造关管线。** 用户在真实项目里做过数据调难度，不需要在作品里再证明；这么小的项目套工业化流程没有意义。批量生成关卡可以有，但不是必须。

- **续命**：花金币买一次额外点击，正式关卡和无尽模式都能用，正式关卡更贵。定价以后再说。

- **美术**：用户嫌球潦草、有锯齿，想以后做漂亮，这轮不碰。
- **文档进 Bloom 的 git，可以正常上 GitHub。** 取代 2026-08-02「干净版不放过程文档」的做法。提交里不要出现 Claude 署名。
- **工作分支可以推到 GitHub**，合并到 `main` 由用户点头。

## 2026-11-02 关卡扩展第一段的技术与规则决定（Fable 定，纯技术）

- **关卡是代码里的数据表，不再是场景。** `LevelCatalog.cs` 每关一个方法，写墙、门、笼子、蛇、摆好的球、随机散布；`LevelBuilder` 运行时搭进唯一的 `Level` 场景。理由：20 多关手摆场景造得慢、改不动，而且总览图和自动测试都要能读到关卡数据。旧 1-5 / 6-10 的场景文件已删除（git 里能找回），旧 6-10 关的几何从场景 YAML 原样抄进数据表。
- **解谜关布局固定**：摆好的坐标或固定随机种子。散布喘息关（1、4、9）保留每次随机。
- **分裂球的规则**：被任何火碰到就炸（算 1 颗），裂出两颗火星，**背着火源**左右各偏 40° 飞，速度 4.5，烧 1.6 秒后自己小炸一下；火星碰到谁谁就着，会被墙和关着的门弹开；火星不算通关数、不吃别人的火。"背着火源飞"是故意的：同一颗五彩球，从左边点着火星往右飞，从右边点着往左飞 —— 这就是「同一个动作在不同局面下后果天差地别」。
- **硬球的规则**：要被两把**不同的**火各碰一次。同一把火贴着它多久都没用。点出来的圈、每颗烧着的球、每颗火星各算一把火。第一次碰只把壳敲掉（外观变普通球）。
- **联动门**：同组的门点一扇全翻转。它把"先把门都开好再点"变成"在飞行中切换"，不加新东西，只是让门和火星咬合。
- **续命**：正式关卡 60、无尽模式 30，占位价，一次尝试最多续一次。**解谜关（`Puzzle = true`）默认不给续命**，否则谜题被花钱绕过去；是不是维持这个默认，等用户拍板。无尽模式失败时本局金币先入账，再问续不续，续命之后再失败只把新增部分入账。
- **蛇遇到关着的门整队停下等**（`HoldWhenBlocked`）是新关卡的选项，旧关卡保持原来"撞到各自散开"的行为。屏幕边界墙改到 Ignore Raycast 层，蛇的探路射线不再把屏幕边界当成门。
- **验证方式**：打一个 macOS 包，无头跑真实游戏代码（`AutoTest.cs`，每帧固定 1/60 秒，结果可复现）。每关跑两类：脚本化的解法（确认过得去）和全屏 12×7 格点的"随手一点"（确认解谜关不会被瞎点过掉）。没有再写一份数学模拟器 —— 门、火星、硬球、逃跑球都用真实代码跑，不会和游戏对不上。旧的 `ChainSimulation.cs` 只给无尽模式的平衡测试用，没动。
- **编辑器便利**：编辑器里全部关卡默认可选（Tools → Bloom → Editor: All Levels Selectable 可关），每次 Play 自动重置后发 300 块测试钱，否则续命按钮永远按不起。都只在编辑器里生效。
- **主菜单每行 6 格**，格子数跟着关卡表走。样关的数字用斜体。
- **新中文文案只用子集字体里已有的字**（续命按钮是「再打一下」），因为手上没有完整的 Noto Sans SC，重新生成字体要下载，属于要问用户的事。关卡名因此暂时不显示在游戏里。
